# Prune stale Claude Code transcripts at Start

Slug: claude-transcripts-grow-without-bound
Model: not applicable — one Start examines a bounded listing of one folder tree once; there is no session state or interacting rule
Acceptance:
- .kogen/intents/claude-transcripts-grow-without-bound/acceptance.feature
- features/steps/claude-transcripts-grow-without-bound__steps.js

Every `Start` of the Claude Code adapter (`executor/claudecode`, `(*adapter).Start` in `executor/claudecode/claudecode.go`) removes session transcripts that no round can resume any more from Kogen's managed Claude Code configuration folder, and reports what it did in the `executor_started` event. Today nothing deletes these files. Claude Code writes one file per session at `<ConfigDir(Options.Home)>/projects/<working-directory folder>/<session id>.jsonl` (observed in a real Kogen config folder: `projects/-home-...-<checkout>/1dc6979d-ab91-44a1-858c-fce74fbcfa6a.jsonl`, alongside non-transcript entries such as `projects/<folder>/memory`). The adapter reports `Resume: none`, so a transcript is never read again once its role invocation ends.

Rules:
1. Option. `claudecode.Options` gains `TranscriptRetention *time.Duration`, with a doc comment. nil (the zero value, which existing callers keep) means the default of 24 hours. A non-nil value of 0 or less disables pruning: nothing is examined or removed, and the start event has no `transcripts` key. A positive value is the retention period.
2. Transcript area. The transcript area is `filepath.Join(ConfigDir(Options.Home), "projects")`. The configuration folder path itself is used as the adapter already uses it, including the README-supported case where `config` is a symlink to a directory. If `projects` is absent, not a directory, or a symlink (by `Lstat`), nothing is examined. A working-directory folder is a direct entry of `projects` that is a real directory by `Lstat`. A transcript is a direct entry of a working-directory folder that is a regular file by `Lstat` and whose name matches `^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}\.jsonl$`. Everything else is left alone and counted in no report field. That includes symlinks at any level (never followed, never removed, and never removed through), subdirectories of a working-directory folder, other names, and every path outside `projects`, such as settings, `policy-limits.json`, `plugins`, `sessions` and `session-env`. Empty working-directory folders are not removed. A removal must not reach outside the transcript area through a symlinked path component; for example, open the area with `os.OpenRoot` and remove through that root.
3. This session. The transcript named `<session_id>.jsonl` in any working-directory folder is skipped and counted in no report field, whatever its age. `<session_id>` is the id this Start generated and reports as `session_id`. Pruning therefore runs after the session id is generated. The session id is still generated by the existing `newUUID` from `crypto/rand` (the acceptance makes it all-zero by replacing `crypto/rand.Reader`, which gives `00000000-0000-4000-8000-000000000000`).
4. Age. Read the current time once per Start. A transcript whose `Lstat` modification time is more than the retention period before that time (`now.Sub(modTime) > retention`) is removed. Otherwise it is kept and counted in `kept`. A transcript exactly the retention period old is kept.
5. Bound. At most 10000 directory entries are read per Start. Each entry read from `projects` and from each working-directory folder counts once. Read directories in bounded batches (`(*os.File).ReadDir(n)` with n no more than what remains), so a larger folder is never listed in full. When the count reaches 10000, examination stops and `bound_reached` is true; otherwise it is false. For example, with only `projects/-home-dev-bulk/` holding 10050 old transcripts, 1 + 9999 entries are read, 9999 transcripts are removed and 51 remain.
6. Failures. A transcript whose removal fails is not removed and is counted in `remove_failed`. Examination continues and Start does not fail. A working-directory folder or `projects` that cannot be opened or read is skipped without a counter. Pruning never makes Start fail and never changes Start's error.
7. Placement and report. Pruning runs only on Start's success path: after the session id is generated and the hook files are written, before `executor_started` is emitted. A Start that fails earlier prunes nothing. When pruning is enabled and at least one of `removed`, `kept` or `remove_failed` is nonzero or `bound_reached` is true, `executor_started` carries the key `transcripts`, a JSON object with exactly these keys: `removed` (transcripts removed), `removed_bytes` (the sum of their `Lstat` sizes), `kept` (transcripts kept for age), `remove_failed` (failed removals), all integers, and `bound_reached` (boolean). Otherwise the key is absent, so an empty or missing transcript area leaves the event's keys exactly as today. No other start-event field changes.
8. Documentation. The README section "Claude Code configuration" gains one short paragraph. It says that Start removes session transcripts under `config/projects` that are older than the retention period (default 24 hours, set by `Options.TranscriptRetention`, 0 disables). It also says that symlinks and other configuration files are never touched.

`contract/` and the executor contract (`executor/executor.go`) are not changed: `Resume: none` stays, and existing start-event checks name individual fields.

## Decisions
- At Start, transcripts that no round can resume any more are removed: regular files named for a session id in the configuration folder's transcript area, not modified for the retention period, and not this session's file. (source: request)
- The retention period defaults to 24 hours, is configurable by an option, and 0 disables pruning. (source: request)
- At most a fixed number of entries is examined per Start. Only files inside the transcript area are touched. Symlinks are never followed or removed through. Settings, policy-limit caches, plugins and other configuration files are left alone. (source: request)
- A failed removal is not a task error; it is counted. (source: request)
- The start event reports the files and bytes removed, the files kept for age, the failed removals, and whether the examination bound was reached. (source: request)
- Prune at Start under <ConfigDir>/projects only: candidates are regular <lowercase uuid>.jsonl files directly inside real-directory working-directory folders. Symlinks at any level, other names, subfolders and everything outside projects are left alone and not counted. (decision: D1, round 1) (constraint: A removal must not reach outside projects through a symlinked component) (constraint: Empty working-directory folders stay) (evidence: executor/claudecode/runtime.go; executor/claudecode/claudecode.go; executor/claudecode/args.go) (assumption: The <config>/projects/<folder>/<session id>.jsonl layout comes from a listing of a local Kogen Claude Code config folder outside the repository, not a Kogen-recorded probe. The pinned Claude Code 2.1.312 layout is assumed from that observation.) (source: request)
- The option is Options.TranscriptRetention *time.Duration. nil means 24h. A non-nil value of 0 or less disables pruning, with no report. (decision: D2, round 1) (evidence: executor/claudecode/claudecode.go; contract/fake_claude_test.go) (source: request)
- The examination bound is 10000 directory entries per Start, counting entries read from projects and from each working-directory folder, read with bounded ReadDir batches. bound_reached is true when the count reaches 10000. (decision: D3, round 1) (assumption: The value 10000 is a judgment: large enough that steady-state pruning with a 24 h retention is never cut short on a busy account, small enough that Start stays prompt. No measurement of real account sizes backs it.) (source: request)
- The report is executor_started.transcripts = {removed, removed_bytes, kept, remove_failed, bound_reached}. It is present only when pruning is enabled and something was counted or the bound was reached. (decision: D4, round 1) (evidence: executor/claudecode/artifact_dir_mode_test.go; contract/claudecode_rounds_test.go; executor/claudecode/claudecode.go) (source: request)
- Acceptance runs a generated external Go driver against the public claudecode.Start with a fake pinned claude. The option is set by reflection so the driver compiles on the unchanged tree. The session id is fixed by replacing crypto/rand.Reader with zero bytes. (decision: D5, round 1) (evidence: executor/claudecode/claudecode.go; features/steps/config_permissions.js; features/steps/k-exec-runtime-entry-unusable__steps.js) (assumption: That Go 1.27.2 crypto/rand.Read honours a replaced Reader, and that the driver reaches a successful Start on the unchanged tree, were observed in this session's own scratch runs. They are not Kogen-recorded probes, so readiness's acceptance run is the authoritative check.) (source: request)

## Source comparison
- Problem (transcripts grow without bound and keep copies of source and task text): addressed by rules 1–7. Scenarios "The default retention removes …" and "More entries than the examination bound …".
- Need, default 24 h, configurable, 0 disables: rule 1. Scenarios "The default retention removes …" (2 h kept, 30 h and 90 h removed), "The retention option sets the period" (48 h: 30 h kept, 90 h removed) and "Retention option 0 keeps everything" (no report, every file remains).
- Need, bounded work: rule 5. Scenario "More entries than the examination bound …" uses 10050 transcripts aged 30 h in one folder. Start returns within 15000 ms, reports `{"removed": 9999, "removed_bytes": 99990, "kept": 0, "remove_failed": 0, "bound_reached": true}`, and 51 entries remain.
- Need, only the transcript area is touched; settings, policy-limit caches, plugins and other files are left alone: rule 2. The default-retention scenario keeps `config/settings.json`, `config/policy-limits.json`, `config/plugins` and a uuid-named `.jsonl` inside `config/plugins` (all 90 h old), and a non-session `notes.jsonl` (90 h) inside a working-directory folder.
- Need, symlinks never followed or removed through: rule 2. The symlink scenario keeps a 90 h transcript-named link to `outside/target.jsonl` and the target unchanged. It also keeps a 90 h working-directory link to `outside/workdir` and the 90 h transcript inside the target. A regular 90 h transcript is removed in the same Start. A symlinked `projects` is covered by unit tests only, because it has no observable difference on the unchanged tree.
- Need, failed removal counted and not a task error: rule 6. In the scenario with a read-only working-directory folder (`0555`), Start succeeds and reports `remove_failed: 1`; the locked transcript remains.
- Need, start event report: rule 7. Each scenario checks the exact `transcripts` object.
- Synthetic acceptance 1–6: scenarios 1, 4, 5, 3 ("Retention option 0 …"), 6 ("More entries …") and 7 ("The new session's own transcript …" uses an all-zero random source so the session id `00000000-0000-4000-8000-000000000000` matches a pre-existing 90 h transcript that remains, while another 90 h transcript is removed). Acceptance 1's "2 removed with their byte total, and 1 kept" is `removed 2, removed_bytes 4300, kept 1`.
- Added: the 48-hour scenario shows the option is a period and not only an on/off switch. The non-session `notes.jsonl` and the uuid-named file under `plugins` are counterexamples to "any old file" and "any `.jsonl` anywhere".
- Replaces: k-exec-session-transcripts-pruned. No Intent of that slug exists in this checkout, so there is nothing to remove.

## Tests
- Transcripts more than the retention period old are removed and younger ones are kept and counted, with the default of 24 hours when the option is nil: Start integration tests in `executor/claudecode` (new test file using the existing fake-claude harness and a temp home) plus the default-retention acceptance scenario (integration)
- Age boundary: a transcript exactly the retention period old is kept, and one a second older is removed: unit test of the pruning with a fixed current time (unit)
- A positive `TranscriptRetention` sets the period, and 0 disables pruning with no `transcripts` key: integration tests plus the 48-hour and 0 acceptance scenarios (integration)
- Only regular `<uuid>.jsonl` files directly in working-directory folders under `config/projects` are candidates. Non-session names, subdirectories and files outside `projects` (settings, policy-limit caches, plugins) are untouched and uncounted: integration test plus the default-retention scenario (integration)
- Symlinks are not followed or removed: a transcript-named file link, a working-directory folder link and a symlinked `projects` all leave their targets and themselves untouched: integration tests plus the symlink acceptance scenario (integration)
- A failed removal is counted in `remove_failed`, the file remains, and Start succeeds: integration test with a read-only folder plus the acceptance scenario (integration)
- The examination stops at 10000 entries read: 1 folder entry plus 9998 transcripts reports `bound_reached: false` and removes all of them, and 1 plus 10050 reports `bound_reached: true` with 9999 removed: integration tests plus the bound acceptance scenario (integration)
- This session's own transcript is never removed or counted, even when old: integration test fixing the session id (for example by replacing `crypto/rand.Reader` in a non-parallel test) plus the own-transcript acceptance scenario (integration)
- An empty or absent transcript area adds no `transcripts` key, so the start event's keys stay as today: existing exact-key checks in `executor/claudecode/artifact_dir_mode_test.go` and the `contract/` start-event checks pass unchanged (existing)
- The README describes the pruning, its default, the option and that 0 disables it: review the README text (existing)
