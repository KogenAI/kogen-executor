# Stop external commands after parent death

Give the Claude Code adapter independently surviving parent-death cleanup for its active round's owned process group. SIGKILL of the embedding Kogen process must stop the executor and ordinary descendants that remain in its group, even with quiet, redirected output. This replaces the current reliance on cancellation goroutines and Close running in the owner. Apply the shared round launcher guarantee to Build, Shape and Review. Preserve existing public interfaces and honest native/external behavior; do not raise any limit, timeout or retry.

This is the executor component delivery, not completion of the original cross-repository lock guarantee. Eventual bounded executor cleanup after abrupt death is required here; proving cleanup before Build-lock release and the installed CLI fault test requires coordinator/root follow-up. Do not claim that this change alone prevents a new lock owner racing cleanup.

## Decisions
- Deliver abrupt-parent-death cleanup through the real adapter in kogen-executor; leave strict Build-lock ordering and installed-CLI proof to coordinator/root follow-up, without claiming the original guarantee complete. (source: answer 1)
- Keep native/external success behavior, public CLI and current limits/timeouts/retries unchanged. (source: request)
- Use only temporary directories and exact fixture-owned pids/groups in tests; no process-name/pattern killing, synthetic CPU load or live provider calls. (source: request)

Technical settlement: establish independently surviving custody before an external round can execute work, using a private supervisor and owner-lifetime pipe (or the existing dependency's equivalent only if it actually supports the adapter's descriptors). An EOF caused by owner death must kill the owned group without needing owner code. Never let the executor or its descendants inherit the lifetime writer. Preserve stdin prompt delivery, stdout streaming, stderr redaction and stored-token fd 3; keep supervision descriptors separate. Retire supervision safely after normal group teardown and reap owned direct children during ordinary operation. No new public CLI switch or required embedding-main dispatch is permitted. Keep existing cancellation and Close teardown working. Support the adapter's existing Linux x86-64 and macOS Apple Silicon targets; no deliberate group/session escape containment is added.

The protected Go acceptance driver embeds the real adapter as a parent subprocess. Its fake pinned runtime answers --version and auth status --json locally, consumes the round prompt, then starts an ordinary shell action with redirected stdio. That action records its pid, sleeps 30 seconds and rewrites app.txt from "before\n" to "after\n". Only after both executor and action are observed running does the driver SIGKILL and wait for the adapter owner. It permits 3 seconds for asynchronous cleanup and independently checks absence of live executor/action processes and absence of the delayed write after a further 31 seconds. Defunct, non-running zombies are not live executors; host init reaping is not under adapter control. This observation allowance is not a new production timeout and is not lock-order proof. Assertions run even when the early process check fails. Cleanup targets only fixture-owned pids/groups. The fake makes no model call and sends no misleading result verdict.
