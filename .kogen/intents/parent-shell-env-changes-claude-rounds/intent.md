# Strip parent model, Git and behaviour env vars

Slug: parent-shell-env-changes-claude-rounds
Model: not applicable — the change is a stateless filter of one environment list, with no state or interacting transitions
Acceptance:
- .kogen/intents/parent-shell-env-changes-claude-rounds/acceptance.feature
- features/steps/parent-shell-env-changes-claude-rounds__steps.js

A Kogen round's model, provider route, Git repository and Claude Code behaviour must come only from Kogen's own flags, `setEnv` entries and managed configuration directory, never from the environment of whoever started Kogen. Today `childEnv` in `executor/claudecode/args.go` passes the parent environment minus `stripEnv`, so any variable not on that list reaches the Claude Code child of every role (Build, Shape, Review, and the `--version`/`auth status` subcommands, which all use `childEnv`). Two runs of the same task, model and effort can therefore differ only because different people started Kogen.

Extend `stripEnv` (the same strip step `childEnv` already applies; keep every existing entry) with three families, each introduced by its own comment:

1. Model selectors, request shaping and per-cloud routes. Already stripped at HEAD and kept: `ANTHROPIC_MODEL`, `ANTHROPIC_DEFAULT_OPUS_MODEL`, `ANTHROPIC_DEFAULT_SONNET_MODEL`, `ANTHROPIC_DEFAULT_HAIKU_MODEL`, `ANTHROPIC_SMALL_FAST_MODEL`, `CLAUDE_CODE_SUBAGENT_MODEL`, `ANTHROPIC_CUSTOM_HEADERS`, `CLAUDE_CODE_EXTRA_BODY`, `ANTHROPIC_UNIX_SOCKET`, `ANTHROPIC_BEDROCK_BASE_URL`, `ANTHROPIC_VERTEX_BASE_URL`, `ANTHROPIC_VERTEX_PROJECT_ID`, `ANTHROPIC_FOUNDRY_BASE_URL`, `ANTHROPIC_FOUNDRY_RESOURCE`, `CLAUDE_CODE_SKIP_BEDROCK_AUTH`, `CLAUDE_CODE_SKIP_VERTEX_AUTH`, `CLAUDE_CODE_SKIP_FOUNDRY_AUTH`. Added: `ANTHROPIC_DEFAULT_MODEL`, `ANTHROPIC_DEFAULT_FABLE_MODEL`, `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` (model selectors of the pinned Claude Code release, see Source comparison).
2. Git repository, index, object-store and namespace selectors and configuration overrides: `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_COMMON_DIR`, `GIT_NAMESPACE`, `GIT_CONFIG_COUNT`, every `GIT_CONFIG_KEY_<n>` and `GIT_CONFIG_VALUE_<n>`, `GIT_CONFIG_PARAMETERS`, `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM`, `GIT_CONFIG_NOSYSTEM`. `GIT_CONFIG_KEY_<n>`/`GIT_CONFIG_VALUE_<n>` are indexed, so the strip step drops every variable whose name starts with `GIT_CONFIG_KEY_` or `GIT_CONFIG_VALUE_` (a prefix rule next to the exact-name list; for example `GIT_CONFIG_KEY_0` and `GIT_CONFIG_VALUE_12`). No other `GIT_` prefix is stripped wholesale.
3. Claude Code behaviour: `MAX_THINKING_TOKENS`, `CLAUDE_CODE_MAX_OUTPUT_TOKENS`, `MAX_MCP_OUTPUT_TOKENS`, `BASH_DEFAULT_TIMEOUT_MS`, `BASH_MAX_TIMEOUT_MS`, `BASH_MAX_OUTPUT_LENGTH`, `CLAUDE_BASH_MAINTAIN_PROJECT_WORKING_DIR`, `DISABLE_PROMPT_CACHING`, `DISABLE_PROMPT_CACHING_HAIKU`, `DISABLE_PROMPT_CACHING_SONNET`, `DISABLE_PROMPT_CACHING_OPUS`, `DISABLE_PROMPT_CACHING_FABLE`.

Variables that choose no provider, model, repository or behaviour keep passing through unchanged, in particular `PATH`, `HTTPS_PROXY`, `NO_PROXY`, `AWS_REGION`, `SSL_CERT_FILE`, `LANG`, `GIT_TERMINAL_PROMPT`, `GIT_SSH_COMMAND` and an inherited `GIT_OPTIONAL_LOCKS`. Everything else about `childEnv` stays: the child still gets exactly one `CLAUDE_CONFIG_DIR` (Kogen's), `HOME` when a home is given, the `setEnv` entries (`CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`, `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`, `DISABLE_UPDATES=1`) and `CLAUDE_CODE_OAUTH_TOKEN_FILE_DESCRIPTOR=3` with a stored token. `shapeEnv` is unchanged: the Shape child gets exactly one `GIT_OPTIONAL_LOCKS=0`. No `--model` default or other flag is added; with no requested model the child simply gets none.

Documentation: `docs/configuration.md` and the executor contract's environment list in `docs/executor-contract.md` each name, in backticks and grouped by family, every variable the strip step removes — the pre-existing credential, route, nested-session, effort, scrub, configuration-directory and update entries and all three families above, writing the indexed pair as `GIT_CONFIG_KEY_<n>` and `GIT_CONFIG_VALUE_<n>` — so a user can see which variables Kogen deliberately ignores, and both state the pass-through variables listed above. README.md needs no change.

## Decisions
- Strip the three families (model/request/route selectors, Git repository/index/object-store/namespace selectors and Git configuration overrides, Claude Code behaviour variables) for every role in the existing strip step, with one comment per family. (source: request)
- Keep `PATH`, `HTTPS_PROXY`, `NO_PROXY`, `AWS_REGION`, `SSL_CERT_FILE`, `LANG`, `GIT_TERMINAL_PROMPT` and `GIT_SSH_COMMAND` passing through. (source: request)
- The child still gets exactly one `CLAUDE_CONFIG_DIR`, `HOME` when given and the `setEnv` entries; Shape still gets exactly one `GIT_OPTIONAL_LOCKS=0`. (source: request)
- `docs/configuration.md` and the executor contract's environment list name every stripped variable. (source: request)

## Source comparison
- addressed: Problem/Need family 1 names were already stripped by the earlier route-selector change (`executor/claudecode/args.go` stripEnv at HEAD); they are kept, re-asserted in acceptance scenario 1 and now carry the family comment. Parent `ANTHROPIC_MODEL=x` and `ANTHROPIC_CUSTOM_HEADERS=h` remain covered end to end by scenario 2.
- addressed: "Check variable names against the pinned Claude Code release's documentation": Kogen pins Claude Code 2.1.312 (`executor/claudecode/runtime.go` Version). The Claude Code environment-variable reference https://code.claude.com/docs/en/env-vars (fetched 2026-11-05; it describes the current release, citing versions up to v2.1.314, so it is the closest available documentation, not a 2.1.312 snapshot) documents `MAX_THINKING_TOKENS`, `CLAUDE_CODE_MAX_OUTPUT_TOKENS`, `MAX_MCP_OUTPUT_TOKENS`, `BASH_DEFAULT_TIMEOUT_MS`, `BASH_MAX_TIMEOUT_MS`, `BASH_MAX_OUTPUT_LENGTH`, `CLAUDE_BASH_MAINTAIN_PROJECT_WORKING_DIR`, `DISABLE_PROMPT_CACHING` and exactly four per-model variants `DISABLE_PROMPT_CACHING_HAIKU`, `_SONNET`, `_OPUS`, `_FABLE`; these are the "per-model variants" stripped here. It also documents `ANTHROPIC_DEFAULT_MODEL` ("Model that new sessions start on by default", requires v2.1.236+), `ANTHROPIC_DEFAULT_FABLE_MODEL` (what the `fable` alias resolves to) and `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` (forces one model onto subagents, requires v2.1.257+); they select the model exactly like the listed `ANTHROPIC_MODEL`, `ANTHROPIC_DEFAULT_*_MODEL` and `CLAUDE_CODE_SUBAGENT_MODEL`, so leaving them would keep the reported defect, and they are added to family 1.
- conflicting, kept: `ANTHROPIC_UNIX_SOCKET` does not appear in the current reference page; it is already stripped and the request lists it, and stripping an unknown name has no effect, so it stays.
- addressed: synthetic acceptance 1 maps to scenario 1 (base with every added name, including `GIT_CONFIG_KEY_0`/`GIT_CONFIG_VALUE_0`/`GIT_CONFIG_KEY_12`/`GIT_CONFIG_VALUE_12` for the indexed pair, plus `PATH`, `HTTPS_PROXY`, `NO_PROXY`, `AWS_REGION`, `SSL_CERT_FILE`, `LANG`, `GIT_TERMINAL_PROMPT`, `GIT_SSH_COMMAND`, `GIT_OPTIONAL_LOCKS=1` and inherited overrides of the managed values; exact resulting set; `shapeEnv` yields one `GIT_OPTIONAL_LOCKS=0`).

Scenario 3 therefore runs `git rev-parse --show-toplevel --absolute-git-dir` in the fake claude's working directory, once with parent `GIT_DIR` and once with `GIT_DIR` and `GIT_WORK_TREE` pointing at another repository, and requires the checkout's top level and `.git`, never the other repository.
- addressed: synthetic acceptance 4 maps to scenario 4 (both documents name every stripped variable in backticks).
