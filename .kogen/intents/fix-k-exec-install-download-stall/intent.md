# Count only incomplete downloads as stalled

Slug: fix-k-exec-install-download-stall
Model: not applicable — the change narrows one classification condition evaluated once at the end of a single download attempt; it adds no state and no interacting rules
Acceptance:
- .kogen/intents/fix-k-exec-install-download-stall/acceptance.feature
- features/steps/fix-k-exec-install-download-stall__steps.js
- features/steps/fix-k-exec-install-download-stall__driver.js

An automated review of the landed k-exec-install-download-stall commit found a defect in `downloadBinary` in executor/claudecode/runtime.go, at `stalled := reader.stop()`. If the body idle timer fires after the last byte has been read but before `stop()`, a complete download is reported as `connection stalled` and the install fails. This was reproduced on unchanged main. A scripted transport delivered the whole 39-byte runtime and then ended the stream with a clean EOF only after the 200 ms idle timer had cancelled the request. `ensureRuntime` returned `executor/unavailable: cannot download Claude Code 2.1.312 from http://127.0.0.1:9/2.1.312/linux-x64/claude: connection stalled` and installed nothing.

After this change, an expired idle timer makes an attempt a stall only when the body copy returned an error or fewer bytes than the pinned size arrived. A copy that ended without error and with the full pinned size continues through the existing checks (longer-than-pinned size, SHA-256, file flush, `--version`, atomic publication) as if the timer had not fired. The idle timer itself is unchanged. It still resets on every positive read, still cancels the request when it expires, and still covers the wait for the first body byte. A genuine stall keeps its message and stays non-retried. The request also asks to bound the header wait. Main already does this (commit f701ea1, `doBounded` with `downloadHeaderTimeout`) for every binary attempt and for the manifest request, so this change keeps that behavior and verifies it in acceptance without changing it. No other behavior, setting, constant, message or dependency changes.

## Decisions
- The stall condition becomes `stalled && (copyErr != nil || n < want.size)`. `stalled` is the value `reader.stop()` returns, `copyErr` and `n` are the results of the body `io.Copy`, and `want.size` is the pinned size. The request settles this as "Treat it as a stall only when err!=nil or the size is short". Here `err` means the copy's error. (source: request)
- The order of the existing checks in `downloadBinary` stays the same. Caller cancellation or deadline (`classify(ctx)`) still wins first. A qualifying stall still comes before local write/close failures and the size, digest and flush checks. It returns `cannot download Claude Code 2.1.312 from <source>: connection stalled` and is not retried. So a short body whose end arrives after the timer fired reports `connection stalled`, not `is shorter than its pinned size`. A short body that ends promptly, with no expiry, still reports `the downloaded Claude Code 2.1.312 is shorter than its pinned size: received <n> bytes, expected <size>; nothing was installed`. (source: request)
- The header wait is bound by the existing `doBounded`/`downloadHeaderTimeout` (30 s) for every binary attempt and for the single manifest request. Keep it unchanged; acceptance rows `silent-headers` and `manifest-silent-headers` verify it. The manifest body read happens only under the `KOGEN_CLAUDE_CODE_URL` test seam. The request's Need asks only for the header bound and no unrelated changes, so the manifest body read stays as it is. (source: request)
- Acceptance compiles a supplied Go test into executor/claudecode through `go test -overlay`. That test replaces the package variable `http.DefaultClient` with a scripted transport, so the binary and manifest requests must keep being sent through `http.DefaultClient`, read at request time; do not introduce a per-adapter client. The test also uses these existing package internals, which must keep their current signatures: `New(Options{Home, Stderr})`, the adapter fields `goos` and `goarch`, `setDownloadIdleTimeoutForTest`, `setDownloadHeaderTimeoutForTest`, `setDownloadRetryDelayForTest`, `ensureRuntime`, `Root`, `RuntimePath`, `SeamEnv` and `Version`. Do not add a file named executor/claudecode/intent_late_stall_capture_test.go, because the overlay supplies that path. (source: request)

## Source comparison
- Addressed: Problem "If the idle timer fires after the last byte but before `stop()`, a complete download is reported as connection stalled and fails". Acceptance row `late-eof` delivers the full body, then ends with a clean EOF only after the idle expiry cancelled the request (`endAfterCancel: true`). It expects a successful install, one binary request, no retry line and no stall message. On unchanged main this row is red, which reproduces the finding.
- Addressed: Need "First reproduce it: add a test that fails on current main for exactly this scenario". The `late-eof` acceptance row is that reproduction, and the Build also adds a focused regression test to executor/claudecode/runtime_test.go (see Tests). The scenario holds on main, so the stop-and-report branch of the request does not apply.
- Addressed: Need "Treat it as a stall only when err!=nil or the size is short". Row `late-error` (full body, then a read error after expiry) and row `short-eof` (half the body, then a clean EOF after expiry) must still report `connection stalled` with the binary URL, one request and no retry. Row `prompt-eof` (full body, prompt EOF) installs. Row `short-prompt` (half body, prompt EOF, no expiry) keeps `is shorter than its pinned size` and is not called a stall.
- Addressed: Need "Bound the header wait" and Problem "Stalls during header and manifest fetch are unbounded". The header wait is already bounded on main. Rows `silent-headers` (3 binary attempts, each held 150–1500 ms under a 200 ms header seam, 2 retry lines, `the server did not answer; 3 attempts`) and `manifest-silent-headers` (one manifest request, no binary request, `the server did not answer` naming the manifest URL) keep it executable. The manifest body read is omitted because the Need does not ask for it; see Decisions.
- Addressed: Need "Keep every existing test green; no unrelated changes". The configured Go checks run the existing runtime tests, including TestDownloadIdleProgressAndStall, the header-timeout tests and the local-write-failure tests. Every acceptance row also requires no `.partial-*` directory and an install.lock that can be taken at once.
- Nothing in the request conflicts or is superseded. README, .kogen/project.yaml and the protection contract are unchanged. The required implementation edits are in executor/claudecode/runtime.go and executor/claudecode/runtime_test.go, neither of which is protected.

## Tests
- A complete body whose clean end arrives after the idle timer fired installs instead of failing as stalled: acceptance row `late-eof`, plus a new runtime_test.go regression test that fails on unchanged main. That test replaces `http.DefaultClient` with a transport whose body returns every pinned byte and then returns `io.EOF` only after the request context is cancelled, sets the idle seam to 200 ms, and expects `ensureRuntime` to succeed with the runtime installed (regression)
- After an idle expiry, a copy error or a short size still fails as `connection stalled` and is not retried: acceptance rows `late-error` and `short-eof`, plus the same regression test's short and error cases (regression)
- Without an expiry, complete and short bodies keep their existing outcomes (installed; `is shorter than its pinned size`): acceptance rows `prompt-eof` and `short-prompt`, plus the existing TestInstallsThePinnedRuntime and TestInstallRefusals (existing)
- The header wait stays bounded for binary attempts and the manifest request: acceptance rows `silent-headers` and `manifest-silent-headers`, plus the existing TestDownloadHeaderTimeoutRetriesSilentBinary and TestDownloadHeaderTimeoutSilentManifestIsSingleAttempt (existing)
- Genuine network stalls, progress resets, cleanup and lock release stay unchanged: the existing TestDownloadIdleProgressAndStall and the configured Go checks (existing)
