# Make the final persistence test portable to macOS

Slug: k-exec-final-persistence-test-portable
Model: not applicable — a test-only change; no product code, state or behaviour changes
Acceptance:
- .kogen/intents/k-exec-final-persistence-test-portable/acceptance.feature
- features/steps/k-exec-final-persistence-test-portable__steps.js

Every kogen-executor Build placed on a Mac fails before it changes anything. The pre-Build check runs `go test ./...` on the executor's main branch, and on macOS `TestFinalPersistenceFailures` in `executor/claudecode/persistence_test.go` fails. The test forces a write failure by making the round artifact a symlink to `/dev/full`. macOS has no `/dev/full`, so the session's open of the artifact fails with "operation not permitted" instead of the short write the test expects, and both subtests (`stderr flush`, `stream marker`) fail. On Linux, where `/dev/full` exists, the test passes. No executor change can be built on a Mac until the test is portable.

The current tree differs from that description: the function now starts with an unconditional `t.Skipf` when `/dev/full` cannot be opened. Each subtest also has a dead fallback that symlinks to `/dev/fd/<n>` of a pipe whose read end is closed. So on macOS the test is skipped, not run. Both the skip and the `/dev/full` / `/dev/fd` sinks are removed.

The outcome: `TestFinalPersistenceFailures` forces the same write failure on darwin-arm64 and on linux, with the same mechanism and no skip on either. It keeps checking exactly the same behaviour. A write failure found only while finalizing a round replaces the otherwise successful result with an `executor/failed` error whose Detail is `cannot persist <artifact> after 0 bytes`. Exactly one `executor_round_failed` event names that `artifact` with `kept_bytes` 0. No `executor_round_ended` event is emitted. The two subtests stay as they are: `stderr flush` (artifact `round-1.stderr`, token `a-long-synthetic-token-for-the-buffer` so the one stderr byte `x` from the wrapper is held by the redaction buffer until finalize flushes it) and `stream marker` (artifact `round-1.jsonl`, `StreamPersistBytes = 1`, so the only stream write is the truncation marker at finalize).

Mechanism (decided): the failing artifact is a POSIX FIFO created at the artifact path in the task directory (`filepath.Join(h.task.Dir, tc.artifact)`) with `syscall.Mkfifo` (`0o600`). `syscall.Mkfifo` exists on both darwin and linux. The session opens artifacts with `os.OpenFile(path, O_WRONLY|O_CREATE|O_TRUNC, 0o600)`. On a FIFO, POSIX ignores `O_TRUNC`, and the open blocks until a reader opens the FIFO. A test goroutine opens the FIFO for reading with `os.OpenFile(path, os.O_RDONLY, 0)`, which lets the session's open complete, and then closes it. Every later write by the session then fails with EPIPE, so 0 bytes are kept. Go returns EPIPE for a broken pipe on descriptors other than 1 and 2 instead of exiting on SIGPIPE, on both platforms. The reader must be closed before the round's child process runs, so that finalize-time writes cannot reach an open reader. This ordering must be deterministic, with no sleeps or timing assumptions. Recommended handshake: the test's wrapper script blocks on a second gate FIFO in a `t.TempDir()` directory (`cat '<gate>' >/dev/null`) before `printf x >&2` and the `exec` of the real binary. After closing the artifact reader, the goroutine opens the gate for writing and closes it, which releases the wrapper. If the session never opens the artifact, the goroutine stays blocked and the test fails on its own assertions; a leaked goroutine is acceptable. Within `TestFinalPersistenceFailures`, the `/dev/full` probe and `t.Skipf`, the `/dev/full` symlink, the `/dev/fd` pipe fallback, and any import made unused by their removal (for example `fmt`, if nothing else in the file uses it) are removed.

Boundaries: no production code changes. No other test changes. `TestStderrWriteFailureCountsEveryByte` keeps its own `/dev/full` usage and skip, because the request names only `TestFinalPersistenceFailures`.

## Decisions
- The test forces the same write failure on darwin-arm64 and linux, with no skip on either platform (source: request)
- The behaviour the test checks stays the same: `executor/failed`, Detail `cannot persist <artifact> after 0 bytes`, one `executor_round_failed` naming the artifact with `kept_bytes` 0, no `executor_round_ended` (source: request)

## Source comparison
- Problem (macOS has no `/dev/full`, the open fails with "operation not permitted", both subtests fail; Linux passes): addressed. The failing artifact becomes a FIFO in the task directory, and the function no longer references any `/dev/` path. acceptance.feature scenario 1 (`/dev/`, `Skip`, `Mkfifo`).
- Need "same write failure on both platforms, no skip on either": addressed. Scenario 1 forbids `Skip` in the function body. Scenario 2 requires both subtests to report `--- PASS`, and no `--- SKIP`, on this host.
- Need "keep the behaviour it checks the same" / synthetic acceptance 1: addressed. Scenario 1 requires the function body to keep the subtest names, the artifacts, `StreamPersistBytes = 1`, `"executor/failed"`, `"cannot persist "`, `" after 0 bytes"`, `"executor_round_failed"`, `"executor_round_ended"`, `"kept_bytes"` and `"artifact"`. Scenario 2 runs those assertions for real.
- Synthetic acceptance 2 (`go test -count=1 -run TestFinalPersistenceFailures ./executor/claudecode/` passes with neither subtest skipped, on darwin-arm64 and linux): addressed on linux by scenario 2, which runs that exact command with `-v` added. darwin-arm64 cannot be executed in this Linux acceptance environment. It is covered by the platform-neutral mechanism (no `/dev/` paths, POSIX FIFO semantics), scenario 1, and scenario 3 (`GOOS=darwin GOARCH=arm64 go vet ./executor/claudecode/` type-checks the package's tests for darwin-arm64). An actual darwin run remains the release-time supported-platform check.
- Synthetic acceptance 3 (`go test ./...` passes on darwin-arm64 and linux): addressed on linux by the configured `go-test` check (`GOFLAGS=-trimpath go test ./...`). On darwin, the only reported failure is removed. `TestStderrWriteFailureCountsEveryByte` still skips there, which passes.
- Determinism of the FIFO handshake: scenario 4 runs the test 3 times under the race detector (`go test -race -count=3 ...`), matching the README's `-race` testing command.
- Existing behaviour that is replaced: the `t.Skipf` on a missing `/dev/full`, the `/dev/full` symlink, and the `/dev/fd/<n>` pipe fallback inside `TestFinalPersistenceFailures`.

## Tests
- A write failure found only while finalizing fails the round with `executor/failed`, Detail `cannot persist <artifact> after 0 bytes`, one `executor_round_failed` (artifact, `kept_bytes` 0) and no `executor_round_ended`, on darwin-arm64 and linux, with no skip: update `TestFinalPersistenceFailures` in `executor/claudecode/persistence_test.go` to make the artifact a FIFO whose reader is closed before the child runs, and remove its skip and `/dev/` sinks (regression)
- The rest of the module keeps passing: the configured `go test ./...` check (existing)

## Feasibility
- Scratch probe outside the repository, Go 1.27.2 linux/amd64. `syscall.Mkfifo` created a FIFO. A goroutine's blocking `os.OpenFile(fifo, O_RDONLY, 0)` let `os.OpenFile(fifo, O_WRONLY|O_CREATE|O_TRUNC, 0o600)` succeed. After the reader closed, `Write([]byte("x"))` returned `0, write ...: broken pipe`. `GOOS=darwin GOARCH=arm64 go vet` of the probe, which uses `syscall.Mkfifo`, passed. (probe: exit 0)
- On the unchanged tree, `go test -count=1 -v -run TestFinalPersistenceFailures ./executor/claudecode/` printed `--- PASS: TestFinalPersistenceFailures (…)` and `    --- PASS: TestFinalPersistenceFailures/stderr_flush (…)` / `    --- PASS: TestFinalPersistenceFailures/stream_marker (…)` and exited 0 on linux. `GOOS=darwin GOARCH=arm64 go vet ./executor/claudecode/` exited 0. `go test -race -count=3 -run TestFinalPersistenceFailures ./executor/claudecode/` exited 0 in about 60 s. (exit 0)
- No darwin host is available here, so actual macOS execution remains unobserved. The mechanism depends only on POSIX FIFO behaviour (O_TRUNC ignored on FIFOs, a writer open waits for a reader, EPIPE when no reader is left) and on Go's documented EPIPE handling for descriptors other than 1 and 2.
