# Share the fake Claude runtime across tests

Slug: executor-shared-claude-runtime-fixture
Model: not applicable — this extracts test-only fixture code and keeps its behavior, with no lifecycle state of its own
Acceptance:
- .kogen/intents/executor-shared-claude-runtime-fixture/acceptance.feature
- features/steps/executor-shared-claude-runtime-fixture__steps.js
- features/steps/executor-shared-claude-runtime-fixture__probe/consumer_probe_test.go.txt

Executor owns one reusable fake Claude Code runtime for tests. The fake `claude` that `contract/fake_claude_test.go` defines today moves into the test-only package `github.com/KogenAI/kogen-executor/testkit/clauderuntime`, whose shared entry point is `testkit/clauderuntime/fixture.go`. The package covers `claude --version`, `claude auth status --json` and configured rounds, with directories the caller owns and fully deterministic answers. The package is tested in Executor against the production runtime path (`claudecode.Probe` and a real `claudecode.New(...).Start` session), no production package imports it, and a change of the pinned runtime version or size is made in the pin table of `executor/claudecode` only. `contract/` becomes a consumer of the package. Production provider behavior, the public CLI, go.mod/go.sum and every other repository are unchanged.

Interface of `testkit/clauderuntime` (the independent consumer probe of the acceptance calls exactly this):
- `type Options struct { Home, State string; Rounds [][]string; APIKeySource, Checkout string }`. `Home` and `State` are directories the caller owns (normally `t.TempDir()` paths); `Install` writes only under them. `Rounds[i]` holds the stream lines of round i+1 after the init line. `APIKeySource` is the init event's `apiKeySource` (default `none`). `Checkout` is the physical path reported as the init event's `cwd`.
- `func Install(t testing.TB, o Options) *Fixture` installs the fake as an executable POSIX sh script at `claudecode.RuntimePath(o.Home)` (creating its directories) and writes `<State>/round-<n>.jsonl` (the lines of `Rounds[n-1]`, one per line) for each configured round. It fails the test when `Home` or `State` is empty. The installed file has exactly the pinned executable size of this platform (sparse padding after the script, which exits before it), so the production runtime check accepts it; on a platform without a pin it is left unpadded.
- `type Fixture struct { Home, State string }` holds the two caller paths. `func (f *Fixture) Prompt(t testing.TB, n int) string` returns the bytes the fake read from stdin in round n (`<State>/prompt-<n>.bin`) and fails the test when round n saved no prompt.
- The script answers `--version` with `<claudecode.Version> (Claude Code)` and a newline, and `auth status` with the single line `{"loggedIn":true,"authMethod":"claude.ai","apiProvider":"firstParty","subscriptionType":"max"}`; exported `func VersionOutput() string` and `const AuthStatusJSON` give those two answers. Any other call is a round n (n counts calls in `<State>/calls`): it saves its stdin as `<State>/prompt-<n>.bin`, prints a `system`/`init` line (`cwd` = Checkout, `session_id` = the id passed as `--session-id` or `--resume`, `mcp_servers` `[]`, `permissionMode` `acceptEdits`, `apiKeySource`, `claude_code_version` = `claudecode.Version`, `model` `claude-sonnet-5-5`) followed by round n's lines with every `SessionID` token replaced by that session id, then exits 0. A round without configured lines prints the init line only.
- `const SessionID = "@SID@"` and the round-line builders `ResultLine(extra map[string]any) string` (a success result of session `SessionID`, `extra` merged over it), `ToolUseLine(id, name string, input map[string]any) string`, `ToolResultLine(id string) string` and `AssistantErrorLine(code string) string`, which are the same lines the contract suite's helpers build today.
- The version and the pinned size come from package `claudecode`: the version is `claudecode.Version`, and the size comes from a new additive exported `claudecode.RuntimeSize() (size int64, ok bool)` that reads the existing pin table for the running GOOS/GOARCH (`ok` false when unsupported). No version or size literal appears in `testkit/` or `contract/`.

`contract/fake_claude_test.go` keeps only what is specific to the contract suite (its `fakeClaude`, `fakeOptions`, `newFake`, `startFake`, `fakeRun`, `eventLog`, `mustJSON`, `writeJSON`, `realDir`), implemented on top of the shared package; the script, the sizing and the round-line builders live only in `testkit/clauderuntime`. Lower-level fakes whose behavior is genuinely different stay where they are: the re-executed test-binary fake of `executor/claudecode/fake_test.go` and its `writeStandIn` (they are tests inside package `claudecode` and so cannot import a package that imports it), the scripted stand-ins of `executor/claudecode/runtime_verify_test.go`, and the acceptance drivers under `features/steps/`.

## Decisions
- The shared package is `testkit/clauderuntime` with `fixture.go` as its entry point (`Options`, `Install`, `Fixture`, `Prompt` and the round-line builders); the script, size and consts may sit in sibling files of the same package. It is an ordinary non-test package that imports `testing`, as `executor/conformance` already does. (constraint: import path github.com/KogenAI/kogen-executor/testkit/clauderuntime) (constraint: no non-test package outside testkit may import it) (evidence: contract/fake_claude_test.go; executor/conformance/conformance.go) (source: request)
- Home and State are both supplied by the caller and required; the fixture writes only under them and never creates its own temporary directory, so deterministic responses depend only on the options. (constraint: Install fails the test when Home or State is empty) (evidence: contract/fake_claude_test.go) (source: request)
- The pinned version is read from claudecode.Version and the pinned size from a new additive accessor claudecode.RuntimeSize() over the existing pinFor table, because pinFor is unexported and the fixture previously copied the sizes. The accessor adds no behavior. (constraint: edits to existing non-test files under executor/ may only add lines) (constraint: the pin table in executor/claudecode/runtime.go stays the only owner of the version and sizes) (evidence: executor/claudecode/runtime.go; executor/claudecode/fake_test.go; contract/fake_claude_test.go) (assumption: An exported accessor added to package claudecode for test fixtures is assumed acceptable under 'do not edit production provider behavior'; it adds no behavior but does add a public symbol to Executor.) (source: request)
- Only the shared script-installing fake and its round-line builders move; contract keeps its adapter-session helpers (startFake, eventLog); the executor/claudecode internal fake and the features/steps drivers stay. (evidence: contract/fake_claude_test.go; executor/claudecode/fake_test.go; executor/claudecode/runtime_verify_test.go) (source: request)
- The three read-only examples named in the request live in other repositories and are not in this checkout, so they are neither inspected nor edited here; consumer adoption is downstream work and is not claimed. (evidence: consumes/README.md) (assumption: The consumer repositories (kogen, kogen-setup, kogen-build) are assumed to adopt the package in their own later changes; nothing here can verify it.) (source: request)
- Acceptance runs the focused go test -race of ./testkit/... and ./contract/...; the full go build, go vet and go test -race -count=1 ./... of README.md is the Builder's required final verification. (constraint: the Build must run the focused contract tests and the full tests including race before it finishes) (evidence: README.md; .kogen/project.yaml) (assumption: The race run of ./executor/... alone exceeded two minutes in this session, so a full race run was not fitted into an acceptance step and was not observed to pass here.) (source: request)
- The shell-script marker, the pinned-size literals and the import graph are verified by acceptance on the final tree; the version and size single-owner claim is verified behaviorally by changing the pin table in a scratch copy and running the package tests there. (evidence: executor/claudecode/runtime.go; executor/claudecode/runtime_test.go) (source: request)

## Tests
- The shared fixture answers `--version` and `auth status --json` and serves configured rounds through the production runtime path, with caller-owned paths and deterministic answers: tests of `testkit/clauderuntime` that use `claudecode.Probe` and a `claudecode.New(...).Start` session on a fixture-installed home (integration)
- A runtime version or size change is made in the pin table only: the package tests pass in a scratch copy whose pin table has another version and sizes (integration)
- The fixture never reaches production binaries and has a single definition: package dependency listing and source checks (integration)
- The contract suite uses the shared fixture and keeps passing: existing `contract/` tests, run with the race detector (existing)
- The lower-level fakes and the rest of Executor are unchanged: the full `go build`, `go vet` and `go test -race -count=1 ./...` (existing)
