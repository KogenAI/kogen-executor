# Secure an existing artifact directory

Slug: k-exec-artifact-dir-private-mode
Model: not applicable — one Start creates, tightens, leaves or refuses one directory; no session state or interacting rules
Acceptance:
- .kogen/intents/k-exec-artifact-dir-private-mode/acceptance.feature
- features/steps/k-exec-artifact-dir-private-mode__steps.js

At Start, the Claude Code adapter (`executor/claudecode.Start` in `executor/claudecode/claudecode.go`) treats an existing artifact directory as private to Kogen. Today Start creates `Task.Dir` with `os.MkdirAll(t.Dir, 0o700)` only when it is absent, and uses an existing directory, including a final-component symlink, without looking at its mode or owner. After this change, an existing directory that is group- or world-accessible, or not owned by this user, is not silently accepted. A directory Start creates, or an existing owner-only directory this user owns, behaves exactly as today: mode `0700` for a created directory, no `artifact_dir_mode_tightened` key, and the same hook files. The config-directory symlink policy in `ensureRuntime` is not this rule and is not changed. `contract/` is not changed.

Rules:
1. Choose the directory. After the existing empty-`Dir` refusal, take `filepath.Abs(t.Dir)`. If the final component is absent, `os.MkdirAll` it at `0o700` as today and do not apply the seams or the tightened key. If `Lstat` shows a symlink, resolve it once: `filepath.Clean(filepath.Join(filepath.Dir(abs), os.Readlink(abs)))`. That result is the directory checked and used. Do not `Readlink` again and do not call `filepath.EvalSymlinks` to choose it. `Join` keeps an absolute link target and resolves a relative one, which is what the acceptance creates (`link -> target`, `hop -> mid -> hop-target`). If the once-resolved path is missing, not a directory, or still a symlink, or `Readlink` fails, refuse with `cannot secure the executor artifact directory <path>: not a directory`. `<path>` is the once-resolved path when `Readlink` succeeded, otherwise the absolute given path. Do not remove or replace the original symlink. A parent symlink is not a final-component symlink: do not resolve it, and keep today's `Abs` spelling in the hook policy.
2. Owner, then mode. These apply only to an existing directory this Start did not create, after one resolution when the final component was a symlink. Read `KOGEN_ARTIFACT_DIR_FOREIGN_OWNER`. If it is set and non-empty, or `fi.Sys().(*syscall.Stat_t).Uid` is not `os.Getuid()` (including when `Sys` has no `Uid`), refuse with `cannot secure the executor artifact directory <dir>: not owned by this user`. Do this before any chmod. Otherwise, if `fi.Mode().Perm()&0o077 != 0`, tighten with `os.Chmod(dir, 0o700)`. If `KOGEN_ARTIFACT_DIR_CHMOD_FAIL` is set and non-empty, do not call `Chmod` and refuse with `cannot secure the executor artifact directory <dir>: cannot change its mode: operation not permitted`. A real `Chmod` error uses that same sentence with `err.Error()` in place of `operation not permitted`. If the permission bits have no group or world access, do not chmod and do not consult the chmod seam. Setuid, setgid and sticky are not a reason to tighten.
3. Refusal effect. Every new refusal is `executor.Fail(executor.ReasonUnavailable, detail)`: class `executor`, reason `unavailable`. The detail is one of the sentences above and names the checked directory. Start emits no `executor_started` event and writes no `hook-policy.json`, `claude-settings.json` or `hook-log.jsonl`. The checked directory's mode is unchanged. The old sentences `cannot create the executor artifact directory: ...` and `executor artifact directory: ...` stay for `MkdirAll` and `Abs` failures.
4. Success effect. The chosen directory is the session directory: hook files are created there at `0600`, as today, and both settings `--policy` arguments (`PreToolUse` and `PostToolUse`) and the policy `log` name files in that absolute path. Checkout detection still uses `filepath.EvalSymlinks` of that used path afterwards; it does not choose the path. When a chmod in rule 2 succeeded, `executor_started` carries `artifact_dir_mode_tightened: true` (boolean, not a string). Otherwise the key is absent, not false. No other start-event field changes. The exact keys when the key is absent are `auth`, `claude_code_version`, `contract`, `effort`, `event`, `executor`, `max_turns`, `model`, `role`, `run_id`, `session_id`, `setting_sources`, `version`.

The seams are test-only, like `KOGEN_CLAUDE_CODE_URL`. Production leaves them unset. They do not apply to a directory this Start created.

## Decisions
- An existing artifact directory that is group- or world-accessible, or owned by another user, is not silently accepted. (source: request)
- When this user owns it, Start tightens it to owner-only. When it cannot, Start refuses with a typed `unavailable` error naming the directory, and writes no hook policy or settings file. (source: request)
- A final-component symlink is resolved once, and that resolved directory is the one checked and used. (source: request)
- A directory created by Start, or already owner-only, behaves exactly as today, with no extra event. (source: request)
- When permissions were tightened, the start event carries `artifact_dir_mode_tightened: true`. (source: request)
- Technical choice: group- or world-accessible means `Perm()&0o077 != 0`. Owner-only means those bits are clear. The tightened mode is `0700`, the same mode Start already uses when it creates the directory. (source: request)
- Technical choice: the owner seam is `KOGEN_ARTIFACT_DIR_FOREIGN_OWNER` and the chmod seam is `KOGEN_ARTIFACT_DIR_CHMOD_FAIL`, each active when set and non-empty. The chmod seam's error text is `operation not permitted`. The owner check uses `syscall.Stat_t.Uid` against `os.Getuid()` and runs before chmod. (source: request)
- Technical choice: one resolution is `Readlink` plus `filepath.Clean(filepath.Join(dir, target))`, not `EvalSymlinks`. A still-symlink result is not a directory and is refused without tightening the ultimate target. (source: request)

## Source comparison
- Problem: Start uses an existing group- or world-accessible directory, or a link to one, as it is, and the run record says nothing. Addressed by rules 1–4. The start event names the tightening; a refusal names the directory and writes no hook files.
- Need, existing open directory: tightened to `0700` when owned, with `artifact_dir_mode_tightened: true`. Scenarios for `0755` (the request's example), `0750` (group access only) and `0707` (world access only).
- Need, cannot tighten: not the owner, or chmod cannot change the mode. Scenarios for the foreign seam on `0755` and on `0700`, the chmod seam on `0755`, and both seams together (the owner sentence wins). The detail names `$ABS/dir`. No hook files are written and the mode is unchanged.
- Need, final-component symlink resolved once and used: the `0777` symlink scenario tightens `$ABS/target`, records the key, and puts `$ABS/target` in the policy log and both `--policy` arguments, while `link` remains a symlink. The foreign symlink scenario refuses `$ABS/target`.
- Need, created or already owner-only, no extra event: the absent scenario, the absent scenario with both seams set, the `0700` scenario, and the `0700` scenario with the chmod seam set. Keys are today's thirteen names, with no `artifact_dir_mode_tightened` key.
- Superseded: a two-hop final-component symlink is no longer followed to the ultimate directory. The hop scenario refuses `$ABS/mid` as not a directory; `hop` and `mid` remain symlinks; `$ABS/hop-target` stays `0777` with no hook files.
- Preserved: a parent symlink is not resolved for the used path. The parent scenario keeps `$ABS/parent-link/exec` in the policy log and both `--policy` arguments.
- Omitted: nothing in the request. Config-directory symlinks stay on the `ensureRuntime` rule (use the target, do not change its mode). `contract/` stays, because a directory Start creates still omits the new key and existing start-event checks assert named fields, not the full key set.

- An existing owner-only directory is not chmod'd and the start event has no `artifact_dir_mode_tightened` key, including when the chmod-fail seam is set: harness cases plus the acceptance scenarios (integration)
- The foreign-owner seam refuses an existing directory, open or owner-only, with the not-owned detail, leaves the mode unchanged and writes no hook files: harness cases plus the acceptance scenarios (integration)
- A needed chmod that the chmod-fail seam rejects refuses with the mode-change detail, leaves the mode unchanged and writes no hook files; when both seams are set the not-owned detail wins: harness cases plus the acceptance scenarios (integration)
