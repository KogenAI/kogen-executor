# Name local install write failures; flush runtime

Slug: k-exec-install-local-write-failure-named
Model: not applicable — one installation runs sequentially under the existing install lock; each step either succeeds or ends the installation with one classified refusal, and the only state is the partial directory versus the published version directory, observed directly by the scenarios
Acceptance:
- .kogen/intents/k-exec-install-local-write-failure-named/acceptance.feature
- features/steps/k-exec-install-local-write-failure-named__steps.js
- features/steps/k-exec-install-local-write-failure-named__driver.js

The pinned Claude Code runtime installer is `install` and `downloadBinary` in `executor/claudecode/runtime.go`. It has two gaps today. (1) When writing the downloaded bytes to `<root>/.partial-*/claude` fails locally (disk full, quota, read-only filesystem, file size limit), the error is the network-style `cannot download Claude Code 2.1.312 from <source>: write <file>: <errno text>`. That points the user at the origin rather than at their own disk. A create failure is reported as `cannot create <file>: open <file>: <errno text>`, which repeats the path and does not say the failure is local. (2) The downloaded file is closed and the partial directory is renamed to `<root>/2.1.312` without flushing the file contents or the directory entry. A crash right after installation can therefore leave a published, short or empty runtime. This change names local write failures as local and makes the runtime durable before and after publication. Everything else stays as it is.

`<root>` is `Root(home)` = `<home>/.kogen/claude-code`. `<file>` is the partial runtime file `<root>/.partial-<random>/claude`. `<dir>` is `RuntimeDir(home)` = `<root>/2.1.312`. `<cause>` is the system's wording: when the error is an `*os.PathError` (found with `errors.As`), its `Err.Error()` (for example `file too large`, `is a directory`, `no space left on device`); otherwise `err.Error()`.

Rules:
1. Local write failure. The partial file is still opened with `os.OpenFile(file, os.O_CREATE|os.O_WRONLY|os.O_TRUNC, 0o700)`, after the existing announced-length check, and the body is still copied as today. A failure of that open, of any write of the body to the file, or of closing the file ends the installation with `executor/unavailable` (the existing `unavailable` helper) and exactly one of these details:
   - `local write failure: cannot create <file>: <cause>; nothing was installed`
   - `local write failure: cannot write <file>: <cause>; nothing was installed`
   - `local write failure: cannot close <file>: <cause>; nothing was installed`
   The detail never contains the origin or `cannot download`. A local write failure is never retried, so exactly one binary request is made, no `download attempt ... failed` line is written, and the partial directory is removed by the existing cleanup. The existing precedence holds: context cancellation and the idle stall are classified first, as today. A write error takes precedence over the read error that ends the copy.
2. Network failures are unchanged. A transport error while reading the body (for example `read tcp ...: connection reset by peer`), a non-200 response, an unanswered request or a stall keeps its current `cannot download Claude Code 2.1.312 from <source>: ...` message, its retryability, its retry stderr line and its `; 3 attempts` suffix.
3. File flush before publication. Once an attempt has received and verified the complete body (size and SHA-256), and before the rename that publishes `<dir>`, the downloaded file is flushed to stable storage exactly once. This uses `Sync` on an `*os.File` for that file: the writing descriptor before it is closed, or a descriptor reopened for that file. Failed download attempts are not flushed. If the flush fails, the installation ends with `executor/unavailable` and `cannot flush <file> to disk: <cause>; nothing was installed`. It is not retried, the partial directory is removed and `<dir>` is not created.
4. Directory flush after publication. Right after the successful rename, the parent directory `<root>` is opened with `os.Open` and flushed with `Sync` exactly once, then closed. If the open or the flush fails, `<dir>` is removed with `os.RemoveAll` and the installation ends with `executor/unavailable` and `cannot flush <root> to disk: <cause>; nothing was installed`. If that removal fails as well, the detail instead ends `: <cause>; remove <dir> and run again`. The `kogen: installed ...` line is written only after the directory flush succeeded. No other directory is flushed.
5. Test seam. `func (a *adapter) setSyncForTest(sync func(*os.File) error)` stores the function in a new `adapter` field, next to the existing `setDownload...ForTest` seams in `runtime.go`. When the function is set, both flushes call it with the `*os.File` being flushed (the runtime file in rule 3, the opened `<root>` in rule 4) instead of `(*os.File).Sync`. When it is nil, `(*os.File).Sync` is called. Nothing else uses it.
6. The success path is unchanged. Exactly the two existing stderr lines `kogen: installing Claude Code 2.1.312 into <dir>` and `kogen: installed Claude Code 2.1.312 (sha256 <digest>)` appear (plus the existing retry lines when an attempt was retried). The installed `<dir>/claude` runs and answers its version. Lock, leftover cleanup, manifest seam, size and digest checks, `--version` verification, executable mode and rename stay as they are.

## Decisions
- A failure to create, write or close the partial file ends the installation as unavailable. Its message names the local path, says `local write failure` and includes the system's wording. It is not retried and the partial directory is removed. (source: request)
- Network failures keep their current message and are retried as before. (source: request)
- The downloaded file is flushed before the rename that publishes it, and the parent directory is flushed after the rename. A failure of either is reported as unavailable with the path, and nothing is left published. (source: request)
- The success path and its stderr notices are unchanged. (source: request)

## Source comparison
- Addressed, Problem (1) and Need (1): rule 1 replaces the `cannot download ... from <source>: write ...` detail for local write failures and the `cannot create <file>: open <file>: ...` detail with the `local write failure:` details. Close failure is covered by the same rule.
- Addressed, Need (2) and Problem (2): rules 3 and 4, with rule 4's removal so that nothing stays published.
- Addressed, Synthetic "partial file's directory made to refuse writes after the download starts (a quota or a size-limited writer seam)": row `write`. The origin sends the first 2048 of 4096 announced bytes and waits until `<root>/.partial-*/claude` holds them (`writtenBeforeLimit`). The capture process then lowers its own `RLIMIT_FSIZE` soft limit to 1024 bytes and sends the rest, so the next write fails with `file too large`. The row expects the unavailable reason, the exact local detail without the origin, one request, only the installing stderr line and no partial directory. Row `create` (a directory placed at `<root>/.partial-*/claude` during the manifest request, so the open fails with `is a directory`) covers the create part of Need (1).
- Addressed, Synthetic "connection reset mid-body still reports the network message and is retried as before": row `reset`, where every attempt sends 2048 of 4096 bytes and then a TCP RST. It expects 3 requests, two retry lines and the exact unchanged detail observed on the current tree. Row `reset-once` resets only the first attempt and then installs, with exactly one file flush and one directory flush.
- Addressed, Synthetic "seam that makes the file sync fail": row `file-sync`, through the `setSyncForTest` seam, which answers `injected sync failure` for the regular file. Row `dir-sync` is the directory counterpart from Need (2).
- Addressed, Synthetic "normal installation succeeds, the runtime path exists and runs, no extra stderr line": row `normal`. It expects exactly the two existing stderr lines and that `<dir>/claude --version` answers `2.1.312 (Claude Code)`. The flushes are observed in order: the file holds 4096 bytes while `<dir>` does not exist yet, then `<root>` is flushed after `<dir>` exists. The flushed file is the installed one.
- Fixture literals: version 2.1.312, a 4096-byte shell-script runtime answering `2.1.312 (Claude Code)`, platform linux-x64, loopback test seam `KOGEN_CLAUDE_CODE_URL`. Placeholders `{home}`, `{source}`, `{sha256}`, `.partial-*` and `{addr}` normalize the temporary home, binary URL, digest, random partial suffix and loopback addresses.
- Omitted: no requested behavior is omitted. No setting, retry or other new seam is added.

## Tests
- A create or write failure of the partial file is named as a local write failure with path and system wording, without the origin, with one attempt and no partial directory: acceptance rows `create` and `write`. Also add the create case (a directory at the partial file's path) to the runtime tests in executor/claudecode/runtime_test.go (regression)
- A close failure uses the same local-write classification: no local fault reliably makes `close` fail on a local filesystem and the request adds no seam for it, so it is covered by the shared classification that rows `create` and `write` exercise (scenario)
- A connection reset mid-body keeps the network message and its retries: acceptance rows `reset` and `reset-once` plus the existing TestDownloadTransportErrors and TestDownloadRetryTimingAndFreshBody (existing)
- A failed file flush ends the installation unpublished: acceptance row `file-sync`. Also add a runtime_test.go case using setSyncForTest (integration)
- A failed directory flush removes the published directory: acceptance row `dir-sync`. Also add a runtime_test.go case using setSyncForTest (integration)
- A normal installation flushes the complete file before the rename and the parent directory after it, runs, and writes only the existing stderr lines: acceptance row `normal` and the existing TestInstallsThePinnedRuntime (scenario)

## Feasibility
- On the unchanged tree, a scratch run of the final capture showed every fault reaching the installer. `create` gives `cannot create {home}/.kogen/claude-code/.partial-*/claude: open {home}/.kogen/claude-code/.partial-*/claude: is a directory`. `write` gives `cannot download Claude Code 2.1.312 from {source}: write {home}/.kogen/claude-code/.partial-*/claude: file too large`, with `writtenBeforeLimit` true, one request and no partial directory. `reset` gives three requests, two retry lines and `cannot download Claude Code 2.1.312 from {source}: read tcp {addr}->{addr}: read: connection reset by peer; 3 attempts`, so that row already passes. `reset-once`, `file-sync`, `dir-sync` and `normal` install successfully, with `seam` false and no recorded flushes. These results are the driver's known-bad fixtures.
- A standalone Go 1.27.2 probe confirmed the size-limited writer. After `Setrlimit(RLIMIT_FSIZE)` with a 1024-byte soft limit, a write past the limit returns `write x: file too large` (PathError cause `file too large`) and the process survives, because Go does not die on SIGXFSZ. Restoring the soft limit makes writes succeed again. Opening a directory with `O_CREATE|O_WRONLY|O_TRUNC` fails with `is a directory`.
